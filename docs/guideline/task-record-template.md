# タスク記録テンプレ（Markdown 正本）

タスクごとに 1 つ作成する記録ファイル（`<docs>/notes/T<タスクID>-<件名>.md`）の **骨格正本**。Gate 1 / 2 の通過記録をここに集約する。本ファイルが骨格の唯一の正本であり、[human-checkpoints.md](human-checkpoints.md) はこれを参照する。

> **使い方**: 下記コードブロックを **コピーして** `<docs>/notes/T<タスクID>-<件名>.md` を作成し、`<...>` プレースホルダを埋める。レビュー判定UI部の 3 サブセクション構造（レビュアー向けサマリ／重点観点／レビュアー記入欄）は省略不可。`<details>` 配下（AI 作業ログ部）の見出し体系・粒度はタスク特性に応じて自由に書いてよい。
>
> **人間レビュー時は、本 Markdown から人間向け提示層（HTML）を生成して窓口とする**（[human-checkpoints.md](human-checkpoints.md)「一次情報源（Markdown）とレビュー提示層（HTML 等）の分離」参照）。HTML 見本は [task-record-template.html](task-record-template.html)。

## Gate 1: 設計の承認

### レビュアー向けサマリ

- **確認してほしい観点**: <1-3 件、箇条書き>

### 重点観点
- 影響範囲分析（参照層 / 状態層 / データ層）の網羅
- 三本柱（テスト戦略 / セキュリティ方針 / ドキュメント計画）の確認・更新
- スコープ確定（コア / 後回し / 対象外）
- 依存追加判断（該当時のみ。ADR への参照）
- 完了条件（機能要件 / テスト要件 / ドキュメント要件 / スコープ外宣言）

### レビュアー記入欄

| 承認者 | <氏名・役割> |
| レビュー依頼日 | YYYY-MM-DD |
| 回答日 | YYYY-MM-DD |
| **結論** | **合格 / 差し戻し**（必須） |
| **コメント** | **<自由記述>**（必須・所感や条件付き合格の条件などを記載） |

## テンプレ運用の補足

テンプレ改変可否・判定欄の必須項目・早見表の更新タイミング等の**運用規定の正本は** [human-checkpoints.md](human-checkpoints.md)「テンプレ運用の補足」にある。記入主体・複数レビュアの並列記入・差し戻し時の運用は同「レビュアー連携」を参照する。

要点のみ:

- レビュー判定UI部の **3 サブセクション構造（レビュアー向けサマリ／重点観点／レビュアー記入欄）は省略不可**。
- 判定欄は **結論（合格 / 差し戻し）・コメントが欠落不可**。
- `<details>` 配下（AI 作業ログ部）の見出し体系・粒度は自由。

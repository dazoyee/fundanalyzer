## Step 4: テスト設計

### テストケース（自然言語）

1. **デスクトップ展開状態の初期表示**: デスクトップ幅 (>= 768px) でアクセスすると、サイドバーが w-64 で展開された状態で表示され、「会社一覧」「株価評価」「EDINET 一覧」のテキストが見える
2. **トグルで折りたたみ**: ヘッダーのトグルボタンをクリックすると、サイドバーが w-16 に縮小され、テキストラベルが非表示になる
3. **折りたたみ後のアイコン視認性**: 折りたたみ後も各ナビアイコンが中央揃えで表示される
4. **状態の永続化**: 折りたたみ状態でページを再読み込みすると、折りたたみ状態のまま表示される
5. **再展開**: 折りたたみ状態でトグルボタンを再クリックすると、展開状態（w-64）に戻る
6. **モバイル挙動の無変化**: モバイル幅 (< 768px) では従来どおりハンバーガーボタンがオーバーレイサイドバーを制御する

### 状態遷移マトリクス

| 遷移元 ↓ / 遷移先 → | 展開 (w-64) | 折りたたみ (w-16) |
|---|---|---|
| 展開 (w-64) | - | 許可（トグルクリック） |
| 折りたたみ (w-16) | 許可（トグルクリック） | - |

### 既存テストとの関係

- `Phase8ScreenSnapshotTest`: aside / header / main タグの存在を確認。幅変更は構造に影響しないため変更不要。
- モバイルスナップショットテスト: sm 未満での画面を確認。`sidebarCollapsed` はモバイルに影響しないため変更不要。

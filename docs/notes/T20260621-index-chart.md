## 2. プロトタイピング（ステップ 2）

### htmx 遅延ロード設計

展開クリック時に Alpine.js `x-effect` → `htmx.trigger()` の流れで一度だけ取得する。

```
[ユーザー ▶ クリック]
  → Alpine: open=true になる
  → x-effect: open && !loaded → loaded=true; htmx.trigger(chartDiv, 'load-chart')
  → htmx: GET /v3/index/{code}/summary
  → IndexPresenter: 時系列データ計算 → "fragments/index-summary-chart :: chart" を返す
  → htmx: spinner を chart fragment に差し替え
  → buildLine() で Chart.js 描画
```

再展開時は `loaded=true` なので取得しない（チャートは DOM に残る）。

### デスクトップ展開エリア ワイヤーフレーム（変更後）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐  [銘柄詳細を見る →] │
│ │ 🔵 最新企業価値│ │ 🟡 割安度    │ │ 🟣 グレアム指数│                   │
│ └──────────────┘ └──────────────┘ └──────────────┘                    │
│ ┌────────────────────────────────────────────────────────────────────┐  │
│ │  [初回展開時: スピナー → summaryChart（年次企業価値 + 株価 2本線）]   │  │
│ └────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────┘
```

## 3. 影響設計（ステップ 3）

### 3.1 変更属性チェック

| 変更属性 | 該当 | 理由 |

| データの形（スキーマ） | **なし** | DB 変更なし |

### 3.2 参照層分析

| 変更 | 影響先 | リスク |
|---|---|---|
| `IndexPresenter` 新エンドポイント | `index-table.html` の htmx GET 先 | 低（新規追加のみ） |

| `index-table.html` | `index-v2.html`（th:replace 参照）| なし（フラグメント名・引数変更なし） |

### 3.3 状態層分析

- `loaded:false` を `x-data` に追加。`open` と独立しており干渉なし。
- localStorage は使用しない（チャートは揮発的に保持）。

### 3.4 データ層分析

- `getCorporateDetailView(code)` は既存 ViewService メソッドを呼ぶだけ。DB クエリは既存と同一。
- 1展開につき 1リクエスト増加。ページ上の全行が一度に展開されることはない（ユーザー操作のみ）。

| カテゴリ | 結果 |

| スキーマ変更 | なし |
| セキュリティ | なし（既存認証保護下、コードをパスパラメータで受け取るだけ） |

# fundanalyzer 本番データに基づく分析ロジックレビュー 調査レポート

> 調査日: 2026-07-11
> 調査範囲: 本番 MySQL（HP-PAVILION / fundanalyzer スキーマ・読み取り専用 SELECT）、ローカルソースコード（develop ブランチ）、Flyway マイグレーション履歴

## サマリー

- 本番 DB には約7.5万件の分析結果・約16.5万件のバリュエーション評価・約300万件の投資指標が蓄積され、毎年約3,600〜3,800社をカバーし続けている。データパイプラインの稼働状況は良好。
- 一方で「業種別係数」は40業種すべてがデフォルト値（営業利益倍率10・流動負債比率1.2・資本コスト8%）のままで、業種別バリュエーションの仕組みが実質的に機能していない。
- 割安判定（割引率≥1.2）が全バリュエーションの約45%に付与されており、スクリーニングとしての選別力が弱い。有価証券報告書ベースの企業価値の約15%が負値で、外れ値も桁違い（最大751億円/株）に発生している。
- 四半期報告書（書類種別140/150）の企業価値算出には、BS ストック項目まで年換算してしまう理論的欠陥がコード上確認され、実データでも同一企業・同一期の有報比で大きく乖離することを確認した。
- 指標列（BPS/EPS/ROE/ROA/RIM）は列追加以前の過去データにバックフィルされておらず、有報ベースで約53%が欠損、RIM は約96%が欠損している。
- ポジティブな検証結果として、提出直後の割引率と1年後の株価騰落率には明確な単調関係がある（割引率<0.8: 勝率43.6% ⟶ 2.0〜4.0: 勝率65.8%）。割安判定の方向性そのものは実データで裏付けられた。

## 調査背景・目的

本番稼働中のデータを直接参照し、fundanalyzer の企業価値分析（理論株価・割引率・バリュエーション指標）の妥当性を「算出ロジック × 実データ」の両面からレビューし、①算出ロジック改善、②データ品質・カバレッジ改善、③投資判断への活用方法、④新指標・新機能提案、の4観点でアドバイスすることを目的とする。

## 主要な発見事項

### 1. データ規模・カバレッジ（良好）

- **事実**: 主要テーブルの正確な件数は company 14,438 / analysis_result 75,299 / valuation 165,029 / investment_indicator 3,010,403。
  *出典: 本番DB `SELECT COUNT(*)`（T1）*
- **事実**: 有報（書類種別120/130）の分析は2019年以降、毎年約3,500〜3,800社・4,100〜4,600件で安定している（2018年: 2,963社 → 2023年: 3,817社）。
  *出典: 本番DB 年別集計（Q3）*
- **事実**: 現在コードを持つ企業4,052社に対し、分析済み企業は4,088社（上場廃止企業を含むため分析済みが上回る）。
  *出典: 本番DB カバレッジ集計（Q4）*
- **事実**: 分析の鮮度は維持されている（最新 submit_date は調査日前日、直近90日で2,551件の有報分析）。
  *出典: 本番DB 鮮度集計（Q12・Q13）*

### 2. 業種別係数が全業種デフォルト値のまま（最重要の改善余地）

- **事実**: industry テーブルの40業種すべてが operating_profit_weight=10.0 / current_liabilities_ratio=1.2 / cost_of_equity=0.08 のデフォルト値（マイグレーション時の DEFAULT 句の値）のまま。
  *出典: 本番DB industry 全行（Q5・Q6）、`V0.3.7__add_industry_coefficient.sql`・`V0.3.8__add_rim.sql` の DEFAULT 句*
- **事実**: 企業価値・RIM の算出はこの係数を業種ごとに解決して使う設計（`IndustrySpecification.resolveCoefficient()`）。
  *出典: `src/main/java/github/com/ioridazo/fundanalyzer/domain/domain/specification/IndustrySpecification.java:91-104`*
- **含意**: 「業種別」の仕組みは実装済みだが、実運用では全銘柄一律の係数で評価しており、業種特性（資本集約度・成長性・リスク）が理論株価に反映されていない。

### 3. 割安判定の選別力が弱い

- **事実**: valuation 全165,029件のうち割引率≥1.2（画面上の「割安」表示閾値）が73,846件（44.7%）。負の割引率（企業価値が負）も23,138件（14.0%）。割引率の最大値は2071.1、最小値は-109.7。
  *出典: 本番DB 割引率分布（Q8）、閾値は `application.yml` `app.config.view.discount-rate: 120`*
- **事実**: 直近35日間のスナップショットでも696件中298件（42.8%）が割安判定であり、履歴全体と同水準。
  *出典: 本番DB 直近分布（Q16）*
- **含意**: 市場の半分近くが「割安」になるスクリーニングは実用上の選別力を持たない。原因は (a) 全業種一律の営業利益倍率10倍が現在の市場実勢に対して甘い、(b) 資産性の高い企業（ネットネット株的な BS）を一律に高評価する算出式の構造、の複合。

### 4. 企業価値の外れ値・負値（データ品質）

- **事実**: 有報（120/130）36,245件のうち負の企業価値が5,324件（120: 4,408件 + 130: 916件、約14.7%）。
  *出典: 本番DB 書類種別別分布（Q1）*
- **事実**: 企業価値の極端な外れ値が存在する（最大 75,146,731,520円/株 [企業コード97190・2026-06-23提出]、最小 -12,697,484,288円/株 [90860・2023-06-23提出]）。
  *出典: 本番DB 外れ値抽出（Q11）*
- **事実**: 97190 の外れ値の根本原因は株式総数の取得異常。financial_statement 上の株式総数（financial_statement_id='4'）は 2022〜2025年3月期が約3.12〜3.13億株で推移しているのに対し、2026-03-31 期だけ「9」が登録されている。
  *出典: 本番DB financial_statement 突き合わせ（Q14）*
- **事実**: 負の企業価値の比率は年によらず安定して発生している（有報ベースで2018年10.8%〜2021年19.8%の帯で推移）。
  *出典: 本番DB 年別集計（V1）*
- **含意**: 外れ値はスクレイピング取得値のバリデーション欠如（前年比・桁チェックなし）が原因。負値は実際の負債超過企業も含むが、水準が年次で一定であることから算出式の構造要因（資産軽・負債重の業態が一律マイナスに振れる）が支配的。

### 5. 四半期書類の年換算に理論的欠陥（コード×データ両面で確認）

- **事実**: 企業価値算出式は `(営業利益×倍率 + 流動資産 − 流動負債×1.2 + 投資その他資産 − 固定負債) ÷ 四半期weight × 4 ÷ 株式総数` であり、フロー項目（営業利益）だけでなく **BS のストック項目まで四半期 weight で除して4倍している**。Q1 書類（weight=1）では BS 項目が4倍に膨張する。
  *出典: `src/main/java/github/com/ioridazo/fundanalyzer/domain/value/AnalysisResult.java:206-211`、`QuarterType.java:10-14`（Q1=1, Q2=2, Q3=3, Q4=4、有報は null→ANNUAL_WEIGHT=4）*
- **事実**: 同一企業・同一 document_period の「Q1四半期報告書 vs 有報」の企業価値比を実データで確認すると、2.83倍・6.27倍・5.87倍など系統的に乖離している（10例中7例が1.25倍超）。
  *出典: 本番DB 突き合わせ（Q7）*
- **事実**: 有報（120/130）は weight が null で ÷4×4=等倍となるため影響しない。また画面表示・平均値集計は `app.config.view.document-type-code: 120,130` に限定されているため、この欠陥は保存データ（140/150 の38,913件）に留まり、corporate_view には流入しない。
  *出典: `application.yml:207`、`AnalysisResultSpecification.java:41-42`*

### 6. 指標列のバックフィル欠如による大量欠損

- **事実**: 有報36,245件のうち BPS/EPS/ROE が NULL のものは19,168件（52.9%）、RIM が NULL のものは34,778件（96.0%）。
  *出典: 本番DB 欠損集計（Q2）*
- **事実**: 欠損は提出年で明確に切れている。BPS の NULL 率は2021年以前100%・2022年93.4%・2023年以降0%。RIM の NULL 率は2025年以前100%・2026年55.1%。機能リリース後の新規分析分のみ値が入り、過去分は未補完であることと整合する。
  *出典: 本番DB 年別欠損率（V1）*
- **事実**: BPS/EPS/ROE/ROA 列は `V0.3.0`、RIM 列は `V0.3.8` で後から追加された列であり、追加以前に登録済みの行への再分析（バックフィル）は行われていない。
  *出典: `V0.3.0__create_investment_indicator.sql:1-4`、`V0.3.8__add_rim.sql`*
- **事実**: RIM は「ROE ≤ 0（赤字）の場合は算出しない」仕様のため、バックフィル後も赤字企業分は構造的に欠損する。
  *出典: `AnalysisResult.java:119-127`*

### 7. PER が負の EPS を除外していない

- **事実**: PER 算出は `eps != 0` のみをフィルタし、負の EPS（赤字企業）では負の PER・負のグレアム指数（PER×PBR）が生成・保存される。
  *出典: `IndicatorValue.java:99-104, 113-117`*
- **事実**: investment_indicator 全3,010,403件のうち、グレアム指数が負のものは339,893件（11.3%）、NULL は483,210件（16.1%）、0〜22.5（グレアム基準の「割安」）は1,237,203件（41.1%、非NULL比49.0%）。
  *出典: 本番DB investment_indicator を id レンジ分割で全件集計（21チャンク合計。合計件数はT1の正確カウントと一致）*
- **含意**: グレアム指数を「22.5未満 = 割安」として昇順スクリーニングすると、赤字企業（負のグレアム指数）約34万件が最上位に混入する。また非NULL の約半数が「割安」となる閾値22.5は、米国市場向けの原典基準であり、構造的に低PBRな日本市場では選別力を持たない。

### 8. submit_date 異常値の混入

- **事実**: analysis_result に submit_date = 1970-01-01（UNIX epoch）の行が76件（35社）存在する。サンプル5件はいずれも document_id が `XXXXXXXX`（プレースホルダ文字列）・document_type_code=120・document_period=2020-01-01 であり、正規の EDINET 書類に紐づかないダミー行。
  *出典: 本番DB 年別集計（Q3）、サンプル抽出（Q15）*

### 9. 割引率には1年後リターンに対する予測力がある（ポジティブな発見）

- **事実**: 提出直後（提出後45日以内）の割引率バケット別に、同一書類の提出後300〜400日時点の株価騰落率（submit_date_ratio）を集計すると（対象10,965書類）、割引率が高いほど平均リターン・勝率が単調に高い。

  | 初期割引率 | n | 平均1年後株価比 | 中央値 | 勝率(>1.0) |
  |---|---|---|---|---|
  | <0.8（割高） | 2,733 | 0.989 | 0.970 | 43.6% |
  | 0.8〜1.2 | 1,760 | 1.036 | 0.995 | 48.3% |
  | 1.2〜2.0 | 2,826 | 1.062 | 1.033 | 57.6% |
  | 2.0〜4.0 | 1,969 | 1.122 | 1.080 | 65.8% |
  | ≥4.0 | 166 | 1.131 | 1.080 | 64.5% |
  | <0（負のCV） | 1,511 | 1.266 | 1.003 | 50.3% |

  スピアマン順位相関は 0.16（n=10,965 での明確な正の単調関係）。
  *出典: 本番DB valuation 全件を id レンジ分割で取得しローカル集計（スクリプト analyze_q9.py）。部分データ（76%）と全量の2回実行で同一の単調パターンを確認*
- **事実**: 負の企業価値（割引率<0）のバケットは中央値1.003・勝率50.3%であり、投資情報としてはノイズ。平均値1.266は少数の極端な外れ値による（標準偏差5.5）。
  *出典: 同上*
- **留意**: この検証は上場廃止銘柄の脱落（生存バイアス）と市場全体の地合いを調整していない。バケット間の相対比較としてのみ解釈すべき。

### 10. 画面表示には多段フィルタがあり生データの汚染は緩和されている

- **事実**: 企業一覧画面は、負の企業価値除外・標準偏差外れ値（10000超）除外・最新企業価値が平均×1.1超のみ表示・変動係数0.5超の条件付き除外など多段フィルタを通してから表示される。
  *出典: `ViewCorporateInteractor.java:505-546`、`application.yml:207-212`*
- **含意**: 外れ値・負値は「おすすめ表示」には流入しにくい。ただしフィルタは症状の緩和であり、割安判定45%という選別力の低さや外れ値の根本原因（株式総数の取得異常）は残る。

### 11. 運用面: 本番機がスリープしバッチ実行が阻害されるリスク

- **事実**: 調査中、本番機（HP-PAVILION）は SSH セッション維持中でも短時間で再スリープし、TCP 接続が繰り返し切断された（Wake-on-LAN で都度復帰することを確認）。OS 稼働時間は15日超であり再起動ではなくスリープ遷移。
  *出典: 調査時の SSH 接続ログ（`client_loop: send disconnect: Broken pipe` の反復）、`Win32_OperatingSystem.LastBootUpTime`*
- **含意**: スリープ中は prod プロファイルのスケジューラ（EDINET 取得・株価取得・評価バッチ）が実行されない。カバレッジ・鮮度は現状維持できているが、実行時刻にスリープしていた日はデータ欠落が起こり得る。

## 考察・分析

### 分析ロジックの妥当性評価

**企業価値算出式は「簡易収益還元＋修正純資産」のハイブリッドであり、方向性は妥当**。営業利益×倍率（収益力）に運転資本・投資資産・負債を加減する構造は、グレアムのネットネット株の考え方と EV 的な発想を組み合わせたもので、割引率バケット別リターン検証が示す通り実際に予測力を持つ。ただし以下の構造的な弱点がある。

1. **係数が全業種一律**（発見事項2）。営業利益倍率10倍は PER 換算で約10倍相当の収益価値であり、成長業種（情報通信）と成熟業種（鉄鋼）を同じ倍率で評価している。資本コスト8%も同様。業種別の仕組みは既に実装済みなので、industry テーブルの係数を設定するだけで改善できる。
2. **資産項目の評価が甘い**（発見事項5の算出式）。流動資産を額面100%で足し込むため、棚卸資産・売掛金の多い企業が過大評価される。グレアム流の掛け目（現金100%・売掛85%・棚卸50〜66%など）を導入する余地がある。割安判定44.7%（発見事項3）の一因。
3. **負の企業価値が約15%発生**（発見事項4）。営業赤字や負債超過の企業は「割安度が計算できない」のであって「割引率が負」ではない。ノイズとして画面フィルタで落とすのではなく、算出段階で「対象外」として区別する方が情報として誠実。
4. **四半期書類の年換算欠陥**（発見事項5）。BS ストック項目は年換算してはならない。営業利益のみ `÷weight×4` し、BS 項目は等倍で扱うのが正しい。四半期報告書制度は廃止されたため新規流入は止まっているが、保存済み約3.9万件の四半期分析値は補正なしでは時系列比較に使えない。

### データ品質の評価

パイプラインの稼働・カバレッジ・鮮度は良好（発見事項1）で、システムとしての基盤は強い。品質課題は「取得値のバリデーション欠如」と「バックフィル欠如」の2系統に集約される。

- 株式総数「9株」のような桁違いの取得異常が無検証で企業価値まで流れ、751億円/株という値が保存される（発見事項4）。財務値の前年比チェック・桁チェックを取得時に入れるのが根本対策。
- 指標列のバックフィル欠如（発見事項6）により、PBR・ROE 系の時系列分析は事実上2023年以降しかできない。過去の有報 XBRL は保存済みのはずなので、再分析バッチで埋められる。

### 投資判断への活用

割引率バケット検証の結果に基づくと、現状の使い方として合理的なのは:

- **割引率 1.2〜4.0 のゾーンを主戦場にする**。全量検証で平均リターン・勝率とも最良なのは 2.0〜4.0 帯（平均+12.2%・勝率65.8%）。≥4.0 は件数が少なく（166件）データ異常の混入率も上がるため過信しない。
- **負の企業価値・グレアム指数が負の銘柄は無視する**。統計的にコイントスと同等。
- **変動係数（corporate_view の coefficient_of_variation）と併用する**。企業価値の年次ブレが小さい銘柄ほど割引率の信頼性が高い。
- 画面の多段フィルタ（発見事項10）は有効に機能しているので、「おすすめ表示」の銘柄を起点にするのは理にかなっている。

## 結論・推奨事項

優先度順。いずれも確認された事実（発見事項番号）に基づく。

### P1: 業種別係数の設定（発見事項2）— 効果最大・実装済み機構の活用のみ

industry テーブルの3係数を業種別に設定する。設定だけで理論株価の質が変わり、割安判定45%の緩さも改善が見込める。出発点として、東証業種別の平均 PER から営業利益倍率を、業種β×市場リスクプレミアムから資本コストを導出する方法がある。

### P2: 財務取得値のバリデーション（発見事項4）— 外れ値の根本対策

株式総数・営業利益等の取得時に「前年同項目との乖離が閾値超なら要確認フラグ」を付け、分析をスキップまたは警告付き登録にする。97190 のような「9株」異常はこれで確実に検出できる。

### P3: 過去データの再分析バッチ（発見事項6）— 時系列分析の解放

保存済み XBRL から2022年以前の BPS/EPS/ROE/ROA と2025年以前の RIM をバックフィルする。document テーブルと財務諸表データは揃っているため、AnalyzeUseCase の再実行で対応可能。

### P4: 四半期分析値の扱い（発見事項5）

新規流入は止まっているため、(a) 140/150 の analysis_result を集計・表示から恒久的に除外していることをコード上明示する、(b) 将来半期報告書等を扱う場合は年換算をフロー項目のみに限定する修正を入れる、のいずれかを明確化する。

### P5: 負の企業価値・負のグレアム指数の扱い（発見事項4・7）

算出段階で「算出対象外」として区別し、割引率・グレアム指数に負値が入らないようにする。PER は EPS>0 のみ算出に変更する（負のグレアム指数は全指標の11.3%・約34万件に及ぶ）。あわせてグレアム指数の割安閾値22.5は日本市場の PBR 水準に合わせた再検討（またはパーセンタイル基準への変更）を推奨する。

### P6: ダミー行のクリーンアップ（発見事項8）

document_id='XXXXXXXX' の76行を特定し、削除または由来を記録する。

### P7: 本番機の電源設定（発見事項11）

スリープによるスケジューラ欠落リスクを解消する（電源プランで自動スリープ無効化、または Wake Timer によるバッチ前復帰）。現状カバレッジは維持できているが、調査中に観測した「SSH セッション中の再スリープ」はバッチ実行中の中断リスクを示唆する。

## 新指標・新機能の提案

蓄積済みデータ（BS/PL/CF・株価・約300万件の指標履歴）だけで実現でき、確認された弱点を補うものに絞る。

1. **パーセンタイル基準のスクリーニング**: 割引率・グレアム指数の絶対閾値（1.2 / 22.5）を「全銘柄中の下位X%」に置き換える。市場全体が割安/割高に振れても選別力が一定に保たれ、割安判定45%問題（発見事項3・7）を設定変更なしで恒久解決できる。
2. **バックテスト画面**: 本調査の Q9 検証（割引率バケット×1年後リターン）をアプリ機能化する。valuation テーブルに必要データはすべて揃っており、係数・閾値を変更した際の効果測定が自走できるようになる。P1（業種別係数設定）の調整サイクルの基盤になる。
3. **修正 NCAV（ネットネット）指標**: 既存の BS 数値から `(流動資産×掛け目 − 総負債) ÷ 株式総数` を算出し、株価との比で表示する。現行の企業価値式より保守的な下値目線を提供し、資産評価が甘い問題（考察1-2）を補完する。
4. **財務値異常アラート**: P2 のバリデーションと対で、前年比乖離が閾値超の取得値を Slack 通知（既存 NoticeUseCase を活用）に流す。97190 型の異常を翌日に検知できる。
5. **ROIC・FCF 利回り**: CF 計算書の数値が取得済みであれば、営業CF−投資CF から FCF 利回りを算出して割引率と併記する。利益ベース（操作されやすい）と CF ベース（操作されにくい）の二重チェックになる。
